**AI & I by Every — Microsoft’s Vision for an Internet Made for Agents With CTO Kevin Scott (Best of the Pod)**

The Takeaway: Model capability is already ahead of product delivery; the bottleneck is an "agentic web" of memory, tools, and open protocols (MCP as HTTP-class plumbing) so agents can act across systems without shipping your org chart.

核心结论：模型能力已经跑在产品交付前面；瓶颈是「agentic web」：记忆、工具与开放协议（MCP 相当于 HTTP 级管道），让 agent 能跨系统行动，而不是把组织架构图直接塞进产品。

Microsoft CTO Kevin Scott argues that last year's scaling-law anxiety has faded because the laws kept working, while reasoning capability now sits in a "capability overhang" relative to what products actually ship. Agents proliferated, so the new hard problems are longer-lived agentic memory (today's agents are too transactional), tool use that can change systems, and an ecosystem that looks like the internet for agent-to-service access. He likens MCP to HTTP for the agentic web and NL Web to HTML's moral equivalent: simple, composable layers that can reach ubiquity.

Microsoft CTO Kevin Scott 认为，去年对 scaling laws 的怀疑已消退，因为定律仍在生效；与此同时，推理能力相对产品实际交付出现了「capability overhang」。Agent 爆发后，真正难的是更持久的 agentic memory（当下 agent 太交易型）、能改动系统的工具使用，以及一个像互联网一样的 agent 访问生态。他把 MCP 比作 agentic web 的 HTTP，把 NL Web 比作 HTML 的道德等价物：简单、可组合、有望走向无处不在。

Inside Microsoft he wants internal systems to speak one standard protocol to company agents so teams do not Conway-law their way into incompatible stacks. On security, he does not claim a finished model, but says MCP's simplicity makes community consensus tractable: agent identities, entitlements, permission requests back to the human delegator, and admin oversight, done openly rather than as a proprietary lock-in. He rejects a hard open-vs-vertical dichotomy, betting on permissionless innovation while arguing AI-native security agents could triangulate risk across modalities.

在微软内部，他推动所有系统对内部 agent 讲同一标准协议，避免 Conway's law 把组织图打进互不兼容的栈。安全上他不宣称已有完美模型，但认为 MCP 足够简单，社区更容易形成共识：agent 身份、权限、向委托人请求许可、管理员监督，而且要以开放方式做，而不是专有锁定。他拒绝把开放与垂直做成非此即彼，既押注无许可创新，也认为 AI 原生安全 agent 可以跨通道交叉核验风险。

On craft and coding agents, Scott refuses purity tests: makers will keep strong tool opinions (he still uses vi), just as woodworkers once argued hand tools vs power tools vs CNC. His advice is blunt: be curious, try things, keep what works. He expects many agents, not one winner, differentiated by product judgment on specific problems rather than novel infra. Looking ahead, waiting because agents are "marginally too expensive or capable" will leave people behind; the next shift is from synchronous prompt-and-wait to asynchronous delegation where agents take time, call many systems, iterate, then hand back.

谈 coding agent 与手艺时，Scott 拒绝纯度测试：maker 会继续对工具有强意见（他自己仍用 vi），就像木工曾经争论手工具 vs 电动工具 vs CNC。建议很直接：保持好奇，多试，好用就留。他预期会是很多 agent，而不是一个通吃王者，差异化来自对具体问题的产品判断，而不是新造一套基础设施。展望上，若还因为「稍微太贵或差一点够用」而观望，会落后；下一阶段是从同步的 prompt-and-wait，转向异步委托：agent 花时间、调用多系统、迭代，再把结果交回。

Memorable line: "MCP [is] serving the same purpose in this agentic web as HTTP does on the internet."
