Latent Space / The Revolution vs The Renaissance — Thariq Shihipar, OpenAI

The Takeaway: After a year of software factories, Thariq Shihipar wants the renaissance side back in the loop: models got wider than "Bash/React is all you need," so the scarce skill is designing human-readable build experiences (like his `/human` scripting folder) that restore taste, dogfooding, and judgment while agents handle the industrial half.

一句话： 软件工厂热了一整年后，Thariq Shihipar 要把文艺复兴这一面拉回环路：模型比「Bash/React is all you need」宽得多，稀缺技能变成设计人类可读的构建体验（例如他的 `/human` 脚本目录），在 agents 负责工业化那一半的同时，把品味、自用测试与判断力装回去。

Thariq Shihipar (just announced joining OpenAI after Anthropic / Claude Code; feed title; ASR often hears "Tariq Schipkar"), closing keynote energy from AIE Code Summit, frames AI as both industrial revolution and renaissance. Factories raise efficiency, reliability, and baseline quality, and also ship a lot of slop. Renaissance is the marginal quality people feel: personal software, higher craft, human-in-the-loop refinement. He says he was wrong that models would stay alien one-trick systems that force everyone into Bash, XML, or React; as they get more general they work the way humans already work, including drawing front ends in Figma, which makes collaboration more legible instead of an unmaintainable dark-factory mess.

刚宣布从 Anthropic / Claude Code 加入 OpenAI 的 Thariq Shihipar（feed 标题用此拼写；ASR 常听成 Tariq Schipkar）带着 AIE Code Summit 闭幕演讲的框架：AI 既是工业革命也是文艺复兴。工厂端抬高效率、可靠性与基准质量，也量产 slop；文艺复兴端是人能感觉到的边际质量：个人软件、更高工艺、人在环路里打磨。他说自己错在以为模型会一直是只会一种做法的「外星物种」，逼所有人只用 Bash、XML 或 React；模型越通用，就越按人类已有工作方式协作，包括在 Figma 里画前端，协作也因此更可读，而不是不可维护的暗工厂乱局。

On building, he rejects vibe-coding fog: when the model invents reasonable game behavior you never specified, playtests feel disorienting. His fix is a `/human` folder whose lint rules force high comment density, no single-character names, and short lines so the files feel like specs while remaining real code he can tweak ("what if this character fired three firewalls at once?"). Defaults are strong (every generated site looks alike; every game gets Shift-to-boost), which is useful until you realize taste starts where defaults end. He is prototyping Frontier Lab, a Civilization-like card game about running a frontier lab with economic / scientific (reach AGI) / cultural victory conditions; Claude ran thousands of sims and always preferred economic victory, then proved bad at rebalancing. Memorable line: "A perfectly balanced game is boring." Rock-Paper-Scissors is fair and dull; interesting metas need variance and recovering "weak" strategies.

在构建上，他讨厌 vibe coding 的迷雾：模型替你做了合理但你从未指定的游戏行为，实玩时会迷失。他的修法是 `/human` 目录：lint 要求高密度注释、禁止单字母变量、限制行长，让文件读起来像 specs，却仍是可改的真代码（「要是这个角色同时放三道 firewall 呢？」）。默认值很强（生成网站长一个样；游戏总会加按 Shift 加速），有用，直到你意识到品味从默认值结束的地方开始。他在做 Frontier Lab：像文明的卡牌游戏，扮演 frontier lab，有经济 / 科学（抵达 AGI）/ 文化等胜利条件；Claude 跑了上千次模拟总选经济胜利，再改平衡也很差。难忘一句：「完美平衡的游戏很无聊。」石头剪刀布公平却乏味；有意思的 meta 需要方差，以及让「弱势」策略也能翻盘。

He does not feel bottlenecked by tokens or even intelligence on $200 plans ("maybe I'm bottlenecked by ambition") so much as by ways of working with models: decision / system-one models in harnesses for support-bot-like trees, weights-based editing experiments, multi-agent shared scratchpads, and personal Mac/iPhone software that is cheap to prototype and hard to keep using (he built then abandoned a focus dock). On RSI he doubts fully headless self-improvement is even the best option; better if models turn hard technical work into knowledge work (decide experiments, allocate compute, get buy-in) while humans keep the trillion-dollar training-run choices. Games, in his framing, are "prosthetics for achievement" for high-stakes practice before the real stakes arrive.

他不觉得自己被 $200 套餐的 token 卡住，甚至不太觉得被智力卡住（「也许我被野心卡住了」），真正卡的是与模型协作的方式：在 harness 里用 decision / system-one 模型做客服树状路由、做 weights-based editing 实验、让多 agent 共用一个 txt/markdown scratchpad，以及便宜可做却难持续使用的个人 Mac/iPhone 软件（他做过又弃用一个 focus dock）。谈到 RSI，他怀疑完全无头自改进是否真是最优；更好的图景是模型把硬技术活变成知识工作（定实验、分配算力、争取共识），而人类仍握住价值万亿的训练 run 决策。游戏在他嘴里是「成就的假肢」：在真实高风险到来前，先练组织、期限与判断。
